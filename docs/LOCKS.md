# Locks  (tags: [Alex]=Alex decided, [Cast]=layout from Cast, [assumption]=ours, needs confirmation)
- [Alex] Signed int4. Host does scale and zp. No on-chip ReLU, bias or scale.
- [Alex] Single-edge clock. Target 66 MHz in and 33 MHz out on pads.
- [Alex] ui_in+uio are all inputs: 8b data + 8b instr every cycle. uo_out = 4 data + 4 flags live. A debug freeze may take all 8 outputs.
- [Alex] Instr [7:4] opcode, [3:0] args.
- [Alex] RTL parameters HAS_OUTBUF and OP_PLACE (0: bus→left buffer→top; 1: swapped). These are real parameters, not ifdef only.
- [Alex] Cfg A HAS_OUTBUF=1: outbuf, dump runs in parallel with RUN, DUMP_LOAD, DUMP_ABORT. Cfg B HAS_OUTBUF=0: no DUMP_*, sums are read with DBG_PSUM, and RUN is forbidden during a debug read.
- [Alex] RUN = one full MAC step = 2 clocks. A second RUN while busy is ignored and sets sticky illegal (once).
- [Alex] LOAD fills the 8b input buffer in 1 cycle.
- [Alex] Dump order PE(2,2)(2,1)(1,2)(1,1). Host endian. 24b partials. Wrap + sticky OVF.
- [Alex] CLEAR args [0]flags [1]inbuf [2]outbuf [3]PE sums. Any collision (PE during RUN, or outbuf during dump_busy) means the whole CLEAR is ignored and illegal is set.
- [Alex] OVF and illegal stay sticky until CLEAR flags. dump_busy, debug_busy, run_busy and dump_paused are level signals. Reset gives known zeros.
- [Alex] Pause = chip hold; the board keeps clocking. There is no plain DUMP opcode.
- [Alex] Live flags nibble = {OVF, illegal, dump_busy, debug_busy} (preferred).
- [Alex, product A 2026-10-31] **TT product = Cfg A, HAS_OUTBUF=1** (RUN ∥ dump). Cfg B is an RTL param build for comparison quotes only. Spec: docs/SPEC.md.
- [Alex, product A] Nibble endian = little: low nibble of each 24b partial first, 6 nibbles × 4 PEs, PE order (2,2)(2,1)(1,2)(1,1).
- [Alex, product A] LOAD byte = two int4 lanes {hi=lane1, lo=lane0}. OP_PLACE=0: old left→top, new byte→left. OP_PLACE=1: old top→left, new byte→top.
- [Alex, product A] Idle live data nibble = 0 when no dump; flags in uo[7:4] stay live.
- [Alex, product A] RUN during a debug freeze is allowed in A. B still forbids it (ignored + illegal).
- [assumption] PE(i,j) += left[i]*top[j], i,j∈{1,2}.
- [assumption, superseded 2026-11-01 by 33 MHz pad-out below] A DBG_* read freezes uo_out for 1 cycle (the next cycle) with debug_busy high.
## Golden-proven host rules (detail in LESSONS)
- [Forge, F7; amended R8-U9/D7] Live flag bits: uo[4]=OVF uo[5]=illegal uo[6]=dump busy at start of the displayed edge. Live (unfrozen) uo[7] reads 0 and is NOT a debug-busy indicator. Debug busy is visible only as bit 3 of a frozen DEBUG_FLAGS byte (DBG_FLAGS bank0[3:0] layout unchanged).
- [Forge, R3-F12] DUMP_LOAD is illegal if the dump was busy at cycle start, incl. the final-nibble cycle; no restart.
- [Forge, F1/R2-F8] CLEAR collisions use busy-at-start: PE vs RUN in flight incl. phase 2; outbuf vs dump busy incl. final nibble.
- [Forge, R3-F15] DBG_ADD on RUN phase 2 = low(wrap24(psum+mul)) preview; else low(psum); never sets OVF.
- [Forge, R2-F10] Only a freezing DBG pauses the dump (no nibble lost). Illegal non-freeze DBG does not pause.
- [Forge, Alex GO 2026-10-31 timing rev; pad-out part revised 2026-11-01] Pad pipeline: ui_in/uio_in are registered at the top (sampled on edge k, executed on edge k+1). All 8 uo_out bits come from one register, loaded once per beat (see 33 MHz lines below). Pin latency: an op applied before edge k shows its result on uo_out after edge k+2 when edge k+1 is an out_tick, else after edge k+3. Reset loads NOP into the input flops and 0 into uo_out. Core semantics (R1-R6) are unchanged except the dump advance and freeze stretch; golden exposes them as `chip_core_step`, and `chip_step` is the pin-level model.
- [Forge, timing rev] ena is registered once (resets to 1): an ena-driven hold takes effect one edge after the pad changes. Golden does not model ena.
- [Forge, Alex GO 2026-11-01 33 MHz pad-out] Core clock stays 66 MHz (15.15 ns), single rising edge. `out_phase_q` resets to 0 and toggles on every enabled edge. An edge is an **out_tick** when out_phase_q=1 before it. The uo_out register loads only on the edge after an out_tick, so the pins change at most once per 2 clk (one **beat**, ≤33 MHz). All 8 bits are gated: the live flags and nibble, or a frozen debug byte.
- [Forge, 33 MHz] The dump nibble advances only on an out_tick, and not while the core output is frozen. 24 nibbles take 24 out_ticks: dump_busy lasts 48 core clocks after a DUMP_LOAD executed on a non-tick edge, and 49 when DUMP_LOAD lands on a tick edge.
- [Forge, 33 MHz] A freezing DBG_* holds the core output for 2 core edges (its own edge and the next), so exactly one out_tick sees it. On the pins the frozen byte lasts exactly one beat (2 clk). The dump hold covers every out_tick inside that window, so no nibble is lost. Supersedes the old "[assumption] freeze for 1 cycle" line. Two freezing DBG_* on consecutive edges are outside the host contract: what reaches the pins depends on the beat phase (R7-F1/F2). If the first lands on an out_tick, both bytes show for one beat each. If not, only the later one shows. Host rule: space debug reads at least 2 edges apart (op, NOP). Spaced reads always give one byte per beat, in order, on either phase.
- [Forge, 33 MHz] Core timing is unchanged: RUN takes 2 clocks, commands still go through the 2-edge input pipeline, and illegal/collision rules use busy-at-start per core edge. Cfg B "RUN during a debug read" still means the edge right after a freezing DBG. Pin latency: an op applied before pin edge j executes on edge j+1. Its result is on uo_out after edge j+2 (if j+1 is an out_tick) or after j+3 (freeze stretch, or the next tick). Golden `chip_step` models this exactly. `chip_core_step` is the per-edge core with the tick gating.
- [Forge, 33 MHz] The host knows the beat phase by counting clocks from reset. The phase is also visible on the pins: dump_busy and debug bytes change only on beat boundaries.
- [Forge, R7-D0/B4b] Live uo[6] is dump busy *at the start of* the edge whose nibble is on the pins, so it means "uo[3:0] is a real dump nibble". The DUMP_LOAD edge shows uo[6]=0 (no junk beat). The final nibble beat shows uo[6]=1. The beat after it shows 0. Pin framing: the dump nibbles are exactly the unfrozen beats with uo[6]=1, in order, on either phase. **[Amended R8-U3/D1]** "Unfrozen" must be tracked by the host: no pin marks a frozen beat (live uo[7] does not). For each freezing DBG_* the host applied before edge j (§2 / 33 MHz numbering above), drop the beat that contains the uo_out value after edge j+3; that beat is frozen even if uo[6]=1. Framing on uo[6] alone without freeze tracking is false during dump+DBG. **[Amended R8-U4/D2]** The host MUST count 24 nibbles. For a visible gap, NOP until a clear uo[6]=0 beat before the next DUMP_LOAD. DUMP_LOAD → nibble 0 latency at the pins is 3 or 4 edges, set by the phase.
- [Forge, R7-F4] DUMP_ABORT on the held (stretched freeze) edge leaves dump_paused=0. paused is set only while the dump is still busy after the edge.
- [Forge, Scribe pass] DUMP_ABORT with no dump running is a legal no-op. Product A uses OP_PLACE=0. An ena hold also freezes out_phase_q: the beat phase resumes where it stopped (intended; golden does not model ena).
- [Forge, R8-U5] Host contract (no RTL change at 677ce98): after DUMP_ABORT wait ≥1 beat (2 clk) before DUMP_LOAD. Whether the ABORT beat shows uo[6]=0 is phase-dependent as measured by Cast R8; do not rely on it as a separator.
- [Forge, R8-S6] SDC multicycle (setup 2 / hold 1) is scoped `-from [get_clocks clk] -to uo_out[*]`, so async rst_n→uo_out keeps single-cycle constraints.
- [Forge, R8-G1, GAP] RTL lockstep not re-run at this absorb: iverilog/verilator absent on box. tb drives ena=1 only; ena-hold of out_phase_q remains unverified in sim.
- [Forge, Scribe pass-c] ena hold: hold edges = edges where registered ena_q=0 (one edge after the pin). in_d_q/in_i_q load only when en=1, so commands on the pads only during a hold are not sampled; the pads on the first enabled edge after the hold are captured. All state incl. out_phase_q freezes and resumes. Golden does not model ena.
